# Transfer codes — wire format

Web source: `parkpass-web/src/lib/passcode.ts`. Test vectors:
`shared/passcode-vectors.json` (generated by the web codec).

Transfer codes replace accounts: the whole board packs into one short string
that can be pasted on another device. **Every platform must produce and
accept the exact same codes.** A code made on an Android phone has to import in
a browser and on an iPhone, and the other way round. Don't improvise: implement
this spec, then prove it by replaying every vector.

Example: `PARKPASS-3000-0004-NRW9` is Abisko pinned on 2026-07-24.

## Constants

| Name | Value |
|---|---|
| Prefix | `PARKPASS` |
| Version | `1` (4 bits) |
| Bitmap width, v1 | 31 bits |
| Date field | 14 bits, days since the epoch |
| Epoch | 2020-01-01 (UTC calendar day) |
| Day `0` | reserved: "pinned, date unknown" |
| Alphabet | Crockford base32, `0123456789ABCDEFGHJKMNPQRSTVWXYZ` |
| Checksum | CRC-16/CCITT-FALSE, low 10 bits, 2 characters |

### CODE_ORDER (frozen, append-only)

The bitmap is positional over this list. **Never reorder or remove entries.**
That would silently remap every code already written down. If Sweden gets a
32nd park, append it and add a version 2 with a wider bitmap; never widen v1.

```
 0 abisko             11 tofsingdalen      22 gotska-sandon
 1 vadvetjakka        12 fulufjallet       23 asnen
 2 stora-sjofallet    13 hamra             24 stenshuvud
 3 padjelanta         14 farnebofjarden    25 dalby-soderskog
 4 sarek              15 garphyttan        26 soderasen
 5 muddus             16 tyresta           27 kosterhavet
 6 pieljekaise        17 angso             28 tiveden
 7 haparanda-skargard 18 namdoskargarden   29 djuro
 8 bjornlandet        19 norra-kvill       30 tresticklan
 9 skuleskogen        20 store-mosse
10 sonfjallet         21 bla-jungfrun
```

This is **not** the display order in `parks.json`. Keep it as a constant in
code, not in data.

## Encoding

1. Start an empty bit stream (most-significant bit first throughout).
2. Write the version: `1` in 4 bits.
3. For `i` in 0…30: write 1 bit, `1` if `CODE_ORDER[i]` is pinned, else `0`.
4. For each pinned park, in CODE_ORDER order, write its day number in 14 bits:
   - Parse the stored date as `YYYY-MM-DD`. If it doesn't match the pattern
     or isn't a real calendar date (e.g. `2026-02-31`), the day is `0`.
   - Otherwise day = the number of calendar days from 2020-01-01 to that date,
     **clamped to 1…16383**. Dates before 2020-01-02 become 1, and dates after
     2064-11-08 become 16383.
5. Pad with `0` bits to a multiple of 5.
6. Split into 5-bit values, each 0…31.
7. Checksum = `crc16(values) & 0x3FF`, computed over the **values** (not the
   bits or the characters). Append `(checksum >> 5) & 31`, then `checksum & 31`.
8. Map each value to `ALPHABET[value]`.
9. Group into chunks of 4 characters joined by `-` (the last chunk may be
   shorter), and prefix with `PARKPASS-`.

### CRC-16/CCITT-FALSE, over 5-bit values

```
crc = 0xFFFF
for v in values:
    crc ^= (v << 8) & 0xFFFF
    repeat 8 times:
        crc = ((crc << 1) ^ 0x1021) & 0xFFFF  if crc & 0x8000
              (crc << 1) & 0xFFFF             otherwise
```

## Decoding

Input is anything the user pasted. Be forgiving about formatting and strict
about content.

1. Uppercase it and drop every character not in `[0-9A-Z]` (dashes, spaces,
   newlines, punctuation).
2. If it starts with `PARKPASS`, remove that prefix.
3. If nothing is left:
   - the original input was blank or whitespace → error **`empty`**
   - the cleaned string was non-empty (e.g. `PARKPASS-` alone) → **`length`**
   - otherwise (e.g. `!!!`) → **`charset`**
4. Map each character to its value. Accept the Crockford aliases `O`→0, `I`→1,
   `L`→1. Any other character outside the alphabet (e.g. `U`) → **`charset`**.
5. If there are ≤ 2 values → **`length`**.
6. Split off the last 2 values as the checksum. If `(hi << 5) | lo` ≠
   `crc16(data) & 0x3FF` → **`checksum`**.
7. Expand the data values to bits (5 per value). If there are fewer than 4 bits
   → **`length`**.
8. Read the 4-bit version. If there's no bitmap width known for it →
   **`version`**. (This check comes after the checksum on purpose: a code
   from a newer app still reports "update this device", not "typo".)
9. If there are fewer than `4 + width` bits → **`length`**. Read the bitmap and
   collect the pinned slugs in CODE_ORDER order.
10. If there are fewer than `4 + width + 14 × pinned` bits → **`length`**.
11. For each pinned slug, read 14 bits as a day:
    - day `0` → today's local date
    - otherwise → `2020-01-01 + day` days, formatted `YYYY-MM-DD`
    - skip slugs that aren't in the current park dataset
12. Return the resulting map. The caller [merges](storage.md#merge-rules-used-by-transfer-code-import) it.

Error precedence and messages are listed in
[profile.md](profile.md#4-transfer-card-move-your-pins).

## Verification

`shared/passcode-vectors.json` contains:

- `codeOrder`: must equal the constant above
- `encode[]`: `{ visits, code, decoded }`. `encode(visits)` must equal `code`
  exactly, and `decode(code)` must equal `decoded` (clamped dates show up here)
- `decode[]`: `{ input, result }`, where `result` is `{ ok: true, visits }` or
  `{ ok: false, error }`

The Android unit tests (`android/core/src/test/…/PasscodeTest.kt`) replay the
whole file. The iOS tests should do the same.
