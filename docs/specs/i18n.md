# Internationalisation

Web source: `parkpass-web/messages/sv.json`, `messages/en.json`,
`src/i18n/routing.ts`.

## Languages

- **Swedish (`sv`)**: the default and primary language.
- **English (`en`)**: complete.
- Park names are the same in both. Region and description come from
  `parks.json` (`region.sv`/`en`, `description.sv`/`en`).

### Picking the language

| Platform | Default | Override |
|---|---|---|
| Web | always Swedish at `/`, English at `/en` | language links on the You tab |
| Native | **English if the device language is English, otherwise Swedish** | language switch on the You tab, persisted per app |

On native, the device language decides the default. That's a small upgrade
over the web, which doesn't negotiate. Users with any other device language
(German, Finnish…) get Swedish, since that's the product's primary language.
Android implements this with per-app language preferences, so the choice also
appears in the system Settings → Apps → ParkPass → Language.

## Strings

The catalogue is `parkpass-web/messages/{sv,en}.json`, grouped by screen
(`tabs`, `parks`, `detail`, `map`, `board`, `you`, `meta`). Native apps keep
their own copies in platform format (`strings.xml`, `Localizable.xcstrings`)
**with the same keys**, flattened as `group_key` (for example `detail.pinIt` →
`detail_pinIt`), so a string can be traced back to the web catalogue. When a
string changes on the web, change it everywhere.

Placeholders use ICU syntax on the web (`{count}`, `{date}`, `{region}`), and
the native equivalents use positional format arguments.

### Plurals

These keys are ICU plurals (`one` / `other`) and must be native plural resources:

| Key | Argument |
|---|---|
| `you.toGo` | parks remaining |
| `you.importedPins` | pins added |
| `you.importedDates` | dates moved earlier |

`parks.pinnedCount`, `map.count` and `board.count` are plain strings with a
number, not plurals.

## Formats

| What | sv | en |
|---|---|---|
| Visit date (list, detail) | `24 juli 2026` style: day, short month, year | `24 Jul 2026` |
| Stamp date | `24 JUL 2026` (2-digit day, uppercased, no periods) | `24 JUL 2026` |
| Area | `1 278`, `1,1` (space grouping, decimal comma) | `1,278`, `1.1` |
| Locale tags | `sv-SE` | `en-GB` |

Always format a stored ISO date as a **calendar date**, with no time zone
conversion. The web app parses it at local noon to avoid DST edges; native apps
should parse it as a plain local date (`LocalDate`, `DateComponents`).
